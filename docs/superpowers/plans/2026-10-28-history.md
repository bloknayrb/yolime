# PR6 `feat/history` implementation plan (v1, for multi-angle review)

**Spec:** `docs/plan.md`, section "History", and PR list item 6:
- a history window with a diff;
- retention;
- re-run;
- vocabulary capture.

**Builds on:** PR5, which provides:
- `SettingsHolder` and `KeySource`;
- `LastResult` and its clear generation;
- `CaptureCoordinator.PasteLastAsync`;
- `ClearHistoryAsync`;
- the tray's last-app-window tracking;
- `SettingsWindow` patterns (built in code, `Guarded`, `Confirm`, `Announce`, `WindowSizing`);
- the E2E UI Automation scenarios.

## What the user gets

A **History** window, opened by a left click on the tray icon (instead of Settings) or from the tray menu (no longer greyed out).

**Left: the list**
- The newest runs first, 200 at a time, with "Load older".
- Each row shows local time, mode, app (display name), the first line of the output (or of the raw text), and status: Pasted, Copied, Failed (with the reason), Cancelled, No speech or Interrupted.
- A search box filters on output, raw text and app name, case-insensitive.
- A mode filter (All, Dictate, Prompt, Reply, Raw).
- A banner when history is paused, and an empty state.

**Right: the detail of the selected run**
- Header: time, app, mode, outcome and total time, plus the per-stage status and timings.
- **Output** and **Raw transcript**, both selectable, read-only text.
- **Diff:** a word-level diff from the raw transcript to the output. Removed words are struck through and added words underlined. It is not colour alone, for high contrast and Narrator. Shown only when both texts exist and differ.
- **Context:** collapsed by default, labelled "Context sent to Claude", for Prompt and Reply. Reveal is an explicit click, because it holds another person's message or the user's clipboard.

**Actions** (each enabled only when it applies)
- **Copy output** and **Copy raw.** These go through the executor's `CopyForUserAsync`, so clipboard freshness marks them as ours and they never become Reply context.
- **Re-insert.** Pastes the output into the window that was in front before History opened, which the PR5 tracker records. It restores that window to the foreground and delivers through the executor. The fresh snapshot is both the start and the current target, so the password, elevated, terminal and own-window rules all apply. If there is no such window, it copies instead and says so.
- **Re-run as another mode.** A menu of the other modes. The kept transcript (and context, for Reply) is rewritten in that mode, with no STT. The result is a **new row**, so the original stays as it was, and it goes to the clipboard (a re-run has no target), with the Copied notice.
- **Retry from audio.** Only for retryable rows whose recording still exists. This is the existing `RetryAsync(id)`; the result goes to the clipboard.
- **Add word to vocabulary.** Select a word or phrase in Output or Raw, then press the button, or use the context menu on the selection. It is trimmed, deduplicated case-insensitively, capped at 200 terms, and saved through `SettingsHolder`. The page says "Added" or "Already in your vocabulary".
- **Delete.** Removes the row and its WAV, then checkpoints the WAL. It asks for confirmation.
- **Clear all.** The same as Settings' Clear history, with confirmation. It waits for a run in progress.

**Live:** the list refreshes when a run finishes, through `CaptureCoordinator.RunFinished`, without losing the selection, and when history is cleared or pruned.

## Core (all TDD)

1. **`IHistoryStore.Page(int limit, long? beforeId, string? search, Mode? mode)`**
   - Newest first.
   - The search is a `LIKE` with `ESCAPE` on the output, raw text and process name, and only on the user's own words.
   - Excludes `InProgress`.
   - Parameterised SQL only.
2. **`HistoryStore.DeleteRun(long id)`.** Deletes the row, then its pending WAV, then checkpoints.
3. **`HistoryItem.From(HistoryRow, Func<string?, string> displayName, TimeZoneInfo)`.** A pure projection for the list. It gives the first line, cut to 80 characters with an ellipsis, newlines collapsed, and invisible characters stripped (the PR3 `RewriteRules` strip). It also gives a status label and severity, and the actions available: `CanReinsert`, `CanRerunAs: Mode[]`, `CanRetryAudio`, `CanCopyRaw`, `CanCopyOutput` and `CanShowContext`.
4. **`WordDiff.Compute(string before, string after)`.**
   - A word-level LCS on whitespace tokens, keeping punctuation attached to its token.
   - Returns segments of type `Same`, `Removed` or `Added`.
   - Bounded: above 2,000 tokens a side, it returns a single `Replaced` segment instead of an O(n·m) table.
5. **`DictationPipeline.RerunAsync(long historyId, Mode asMode, ...)`.**
   - Inserts a new row that copies the raw text, context, context source and process name, with the new mode and `InProgress`.
   - Then rewrites it like `RunFromTranscriptAsync` and delivers with `ClipboardOnly` intent.
   - Raw mode needs no rewriter: the output is the cleaned raw text. Dictate uses local cleanup, or the rewriter for long texts, as in a normal run.
   - It goes through the busy gate.
   - With history paused it refuses (the button is hidden).
6. **`CaptureCoordinator.RerunAsync(id, mode)`** (the busy check and overlay progress, as in `RetryAsync`), and **`PasteTextAsync(text, mode)`** generalised from `PasteLastAsync`, which then becomes a call to it. Re-insert uses `PasteTextAsync`. Neither records into `LastResult`: they aren't new results.
7. **`SettingsEdits.AddVocabulary(settings, term)`.** Returns `(settings, AddResult.Added | AlreadyThere | Empty | Full)`.

## App

8. **`HistoryWindow`**, built in code like Settings:
   - a single instance, re-activated when opened again;
   - closed before host disposal;
   - `WindowSizing.SizeAndCentre(1040, 720)`;
   - every control named for Narrator;
   - the status line announced through `Announce`;
   - every async action through `Guarded`;
   - destructive actions through `Confirm`.
9. **Re-insert target:**
   - When History opens, it reads `AppHost.LastAppWindow`, the PR5 tracker, which skips yolime, the shell's windows and cloaked windows.
   - Re-insert calls `SetForegroundWindow(target)`, waits up to 1 s for it to become the foreground window, then calls `PasteTextAsync`.
   - If the window is gone, or the foreground doesn't move, the text is copied and the window says so.
10. **Tray:**
    - Left click and the menu item open History.
    - The menu's "History" item is enabled.
    - "Finish setup…" and Settings are unchanged.
11. **Live refresh:**
    - `RunFinished`, `ClearHistoryAsync` and the retention prune raise an `AppHost.HistoryChanged` event.
    - The window reloads the first page and keeps the selection by id.

## E2E (Sandbox)

12. Scenarios, run after the existing ones:
    - **open:** dictate twice, then open History from the tray command. The list shows the two newest rows, the newest first, with mode Dictate and app `Yolime.E2E`.
    - **Copy output:** puts the row's output on the clipboard.
    - **Re-insert:** History opens over the target form; Re-insert pastes the output into the form's box (the form was the last app window).
    - **Re-run:** re-run as Raw. A new row appears, and the clipboard holds the raw transcript.
    - **Add word:** select a word in Output, press Add. settings.json's vocabulary contains it.
    - **Delete:** delete a row, confirmed. It leaves the list, and no WAV remains for it.

## Out of scope

- A History search over context.
- Export.
- A per-row "play audio" (audio is kept only until it is safe and is never a feature).
- Editing output.

## Review focus (questions for reviewers)

- Re-insert's foreground handoff, and whether the executor's rules all still apply.
- Re-run's new-row semantics against retention, pause and `LastResult`.
- What the window shows by default (context is sensitive).
- The SQL search's injection and performance.
- WordDiff's bounds.
- Narrator and keyboard use of a two-pane window.
- Live-refresh races with a run in progress.

## v2 rulings after four reviews (UI/UX, platform, security, product/architecture). These override the text above.

**Re-insert**

UI/UX and platform want the target read at click time; security wants a recycled handle caught. This design satisfies both.

1. The target is `AppHost.LastAppWindow`, read **when Re-insert is clicked**, not when History opens. The tracker skips yolime, shell windows and cloaked windows.
   - The button names it ("Re-insert into Outlook") and updates as the foreground changes.
   - The tracker records the HWND, PID and process start time. At click time all three must still match, or the text is copied with "that window has closed".
2. **Before switching:**
   - If the target is elevated, copy and say so; don't switch focus.
   - Wait until no key is down. A button invoked with Enter would otherwise send Enter's key-up into the target.
   - If the target is minimised, restore it (`IsIconic`, then `SW_RESTORE`).
   - Then call `SetForegroundWindow`.
3. **Before pasting:**
   - `GetForegroundWindow()` must equal the target, with the same PID, within 1 s. Otherwise copy and say "the window didn't come forward".
   - The start snapshot is taken after UIA focus has settled (up to 300 ms), so a slow focus change can't turn the paste into a copy.
   - The executor's rules apply as usual: password, terminal and own-window.
   - Re-insert doesn't record into `LastResult`.

**Re-run**

4. **A new row with `rerun_of`**, a schema migration.
   - It keeps the **source's `started_ms`**, so a re-run can't extend retention. It sorts beside its source and is labelled "Re-run of 14:32".
   - Deleting a run deletes its re-runs; the confirmation says how many. A delete with no re-runs asks nothing, per Bryan's no-guards stance.
5. The run is new: `Previous = null`. A failure becomes Interrupted on the new row; the source is never touched.
6. **Context** is copied only when the new mode uses it (Prompt, Reply).
   - Reply is offered only when the row has context.
   - Re-run is offered only when the row has raw text.
   - The menu says what costs a Claude call: "Prompt (Claude)", "Reply (Claude)", "Dictate (Claude if long)", "Raw (no AI)".
7. **Rewriter check:** the "rewriter ready" gate applies only to modes that need it. Raw is the transcript verbatim. Short Dictate uses local cleanup.
8. **Delivery:**
   - An explicit `ClipboardOnly` intent, not a missing snapshot.
   - The button is disabled while a re-run runs, and the status line says "Re-running as Prompt...". When it finishes, the new row is selected.
   - The result is recorded into `LastResult` like a retry, so the clipboard and Paste last agree.
   - Cancel is deferred.
9. While history is paused, Re-run is **disabled with the reason** shown, not hidden.

**Store and data**

10. **Paging** is a keyset on `(started_ms, id)` with the same ORDER BY. Orphan adoption gives old times new ids, so paging by id alone would skip or duplicate rows.
11. **Search** runs in C# (`OrdinalIgnoreCase`, so it isn't ASCII-only).
    - It covers the output, the raw text and the **display name**, over the rows retention keeps, capped at 500 hits and debounced at 250 ms.
    - No SQL `LIKE`; search terms are never logged.
12. **Reads run off the UI thread.** A read that finishes after Dispose is caught. A row this build can't parse is skipped, not fatal.
13. **Delete:**
    - It goes through the pipeline's busy gate (`DeleteRunAsync`), so a re-run in flight can't copy a row back after its delete.
    - It is a secure delete, followed by a checkpoint whose `busy` result is checked.
    - It clears `LastResult` when that holds the deleted run's text (`LastResult` keeps the history id).
    - The WAV is a normal file delete. That is accepted: disk-level recovery is out of scope.
14. **Retention:**
    - Pruning also runs on a 6-hourly timer and when History opens, through Housekeeping, plus a checkpoint.
    - Anything pruned raises `HistoryChanged`.
    - The window says "Runs are kept for N days" and links to Settings.

**Window**

15. **Live refresh:**
    - `HistoryChanged` is raised by holds, retries, re-runs, deletes, Clear and prunes, and marshalled to the UI thread.
    - New matching rows are **prepended**. Loaded pages, scroll position and selection are kept.
    - The detail pane is rebuilt only when the selected id changes. A retried row that is InProgress keeps its detail pane.
    - Clear and prune reload fully. If the selected row is gone, the detail pane is blanked at once.
16. **Context:**
    - Collapsed, and **not in the visual or UIA tree** until Reveal is clicked.
    - It collapses again when the selection changes, on deactivation and on reopen.
17. **Capture and memory:**
    - The window is excluded from screen capture under `HideOverlayFromCapture` (on by default).
    - Closing disposes it, so its text isn't kept in memory.
18. **Add word:**
    - It opens a small **editable** box prefilled with the selection (punctuation trimmed), so the user types the correct spelling. It also works with nothing selected.
    - Core `AddVocabulary` refuses newlines and terms over 48 characters, strips Cf and control characters, and reuses `ParseVocabulary`'s dedupe and cap.
    - Results: Added, AlreadyThere, Empty, TooLong, Full (which points to Settings).
19. **Diff:**
    - It has an accessible summary ("4 words removed, 6 added").
    - Above the token bound it says "too long to compare" instead.
    - Removed words are struck through and added ones underlined, as well as coloured.
20. **Keyboard and Narrator:**
    - Every list item has a full name ("Yesterday 14:32, Dictate, Outlook, Pasted, first line").
    - Tab order: search, filter, list, detail, actions. Ctrl+F searches, Delete deletes, Esc closes, F6 switches panes.
    - On open, the newest row is selected and the list has focus.
    - After a delete, focus moves to the next row.
21. **Dates and states:**
    - Dates are relative: "Today 09:12", "Yesterday 14:32", then a date.
    - The empty state teaches the hold key.
    - A database error is its own state, never "nothing yet".
    - The paused banner has a Resume button.
22. **Tray:**
    - A left click opens History, or Finish setup while setup is needed.
    - The menu's History item and `RunCommand(CmdHistory)` work.
    - `AppHost` exposes the last app window.

**Task order** (the risky parts last, so they can be split off):
1. Core store: the migration (`rerun_of`), Page, Search, DeleteRun, and prune with checkpoint.
2. Core: HistoryItem (with relative time), WordDiff, AddVocabulary.
3. Pipeline: `DeleteRunAsync` and `RerunAsync`. Coordinator: `HistoryChanged`, `RerunAsync`, and `PasteTextAsync`, which paste-last now uses.
4. App, the window:
   - list and detail;
   - diff, Copy, Delete and Clear;
   - Add word, context reveal and capture exclusion;
   - live refresh, retention text, and the tray and timer.
5. App: Re-run.
6. App: Re-insert, using an identity tracker of HWND, PID and start time.
7. E2E:
   - open, which also checks the list items' names;
   - Copy;
   - Add word, selecting text with the keyboard;
   - Delete;
   - live refresh (dictate while History is open);
   - Re-run as Raw;
   - Re-insert.

**Deferred:**
- Cancelling a re-run.
- Merging a vocabulary added from History into an open Settings page with unsaved typing (Settings redraws on outside changes).
- Win+V keeps copies (the Copy help text says so).
- Spec wording: "Audio is never stored" means never beyond the pending WAV.
