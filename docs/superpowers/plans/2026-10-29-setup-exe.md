# yolime-setup.exe: an installer for easy installation (v2)

Bryan, 2026-10-29: "can you package yolime as a .exe for easy installation?"

## Goal

One double-clickable `yolime-setup-<version>.exe` that installs, upgrades and uninstalls yolime with no .NET SDK, no
repo and no PowerShell typing. It leaves exactly the install `tools/install.ps1` leaves, because it *is*
`install.ps1` underneath.

## Form factor

- **An installer, not a one-file app.** A self-contained WinUI 3 / Windows App SDK app can't be published as one exe
  (the WinAppSDK runtime DLLs and `Yolime.App.pri` sit beside it). MSIX would make yolime a packaged app (new
  identity, data paths, hook and startup behaviour) and needs signing.
- **Inno Setup 6** builds it. On GitHub's `windows-latest` image (6.7.1); locally `winget install
  JRSoftware.InnoSetup --scope user` (6.7.1 installed 2026-10-29). The `.iss` refuses Inno older than 6.3
  (`x64compatible`).

## Design: Inno is the wrapper, `install.ps1` does the work

v1 reimplemented `install.ps1` in Inno's Pascal. All four reviews found the reimplementation was where the risk was:
- `[InstallDelete] {app}\*` deletes the old install before the copy, with no rollback, so a failed upgrade leaves
  nothing (the script's `.new`/`.old` swap keeps the old one);
- `/DIR=` or the previous-install registry value can point that wildcard delete at any folder;
- finding running copies through the tray window misses copies with no window, and an elevated copy can be neither
  asked nor killed;
- every rule (elevation, reparse points, clean close, Run value) would exist twice and drift.

So the work stays in one place:

- **Two folders, two owners.** `install.ps1` owns `%LOCALAPPDATA%\Programs\Yolime` (the app), exactly as today.
  Inno's `{app}` is a sibling, `%LOCALAPPDATA%\Programs\Yolime Setup`, holding only `unins000.exe/.dat`,
  `install.ps1` and `check-publish.ps1` (for uninstall). Inno never writes, deletes or swaps inside `Yolime`.
  - setup.exe over a script install, and the script over a setup install, both just work: the script swaps the
    `Yolime` folder and the Apps entry is untouched. After `install.ps1 -Uninstall`, the Apps entry remains;
    uninstalling from Apps then finds nothing to remove and clears itself. (README says so.)
- **Install** (`PrepareToInstall`, before Inno writes anything):
  1. `ExtractTemporaryFiles` the publish folder and the two scripts into `{tmp}`.
  2. Run `{sys}\WindowsPowerShell\v1.0\powershell.exe -NoProfile -ExecutionPolicy Bypass -File {tmp}\install.ps1
     -From {tmp}\pkg -LogFile <setup log dir> -SummaryFile {tmp}\summary.txt -StartWithWindows on|off`,
     hidden, and wait.
  3. Exit 2 (new: "yolime is running", nothing changed): GUI asks "yolime is running. Setup will close it the way
     Exit in its tray menu does and start the new version afterwards. A dictation in progress won't be pasted; it
     will be in History to retry." OK / Cancel. Silent proceeds. Then rerun with `-Force`.
  4. Any other nonzero exit: return the script's last message as the error. Inno has written nothing, so there's no
     Apps entry and the old yolime is untouched (the script's own swap guarantees that).
  5. Exit 0: Inno installs its own small files and the Apps entry. The finish page shows `summary.txt` (Installed
     or Upgraded, Start with Windows, Running, the first-run key hint, any Smart App Control warning, the dev-copy
     note), the same lines the script prints.
  - Launching stays the script's job (it already handles a dev copy holding the single instance), so there's no
    "Start yolime" checkbox to get wrong.
- **Uninstall** (from Settings > Apps, `unins000.exe`):
  - `[Messages] ConfirmUninstall`: "Remove yolime? Your settings, history, voice recordings and saved keys are kept
    unless you choose to delete them next."
  - At `usUninstall` (after the confirm): "Also delete your settings, history, voice recordings and saved keys?"
    Yes / No, default No (`SuppressibleMsgBox`, so silent keeps data; `/REMOVEDATA` on the command line says yes).
  - Run `install.ps1 -Uninstall -Force [-RemoveData]` from `{app}`, hidden. If it fails, show its message and raise,
    so the uninstaller stops before removing its own files and the Apps entry (verified in the Sandbox, see tests).
  - `UninstalledAll` lists what's left, or "everything removed" after `-RemoveData`.
- **Elevation.** `PrivilegesRequired=lowest`. `InitializeSetup` and `InitializeUninstall` refuse when `IsAdmin`:
  "yolime-setup is running as administrator. Start it from Explorer without 'Run as administrator': yolime must not
  run elevated, and an elevated setup may install into another account." The bypass for the Sandbox (whose only
  account is an administrator) is compiled only with `ISCC /DSandboxTest`, which passes `-AllowElevated` to the
  script; the shipped setup has no such switch, and the Sandbox test proves the shipped one refuses.
- **The folder is fixed.** `DisableDirPage=yes`, `UsePreviousAppDir=no`, and `InitializeSetup` aborts unless `{app}`
  equals `{localappdata}\Programs\Yolime Setup` (so `/DIR=` can't move it). Inno's folder holds no user files.
- **Metadata.** Fixed `AppId={{GUID}`, `AppName=yolime`, `AppPublisher=Bryan Kolb`, `AppVersion` and the file name
  from the build (below), `UninstallDisplayIcon={localappdata}\Programs\Yolime\Yolime.App.exe`,
  `ArchitecturesAllowed/InstallIn64BitMode=x64compatible`, `MinVersion=10.0.19041`, `CloseApplications=no`,
  `SetupLogging=yes`, `UninstallLogging=yes`, `DisableWelcomePage=yes`, `DisableProgramGroupPage=yes`,
  `DisableReadyPage=no`.
- **Start with Windows.** A task on the setup's one page, "Start yolime when I sign in": checked on a fresh install,
  preset from the current Run value on an upgrade. Silent: unchanged unless `/STARTUP=on|off`.

### `install.ps1` changes (each covered by the existing script tests plus new ones)
- Exit code 2 for "yolime is running" (was 1), so setup can tell it apart. Nothing else changes for script users.
- `-StartWithWindows on|off`: on writes `"<exe>"` (quoted, as `StartWithWindows.CommandFor`); off removes the
  `yolime` Run value and its StartupApproved value. Without it, today's behaviour (re-point an existing value).
- `-SummaryFile <path>`: writes the closing summary block there too. `-LogFile <path>`: `Start-Transcript`.
- `-RemoveData` (with `-Uninstall`): removes `%APPDATA%\Yolime` and `%LOCALAPPDATA%\Yolime` (refusing a reparse
  point at either; `cmd /c rmdir /s /q`, which removes junctions inside without following them) and the four
  `cmdkey /delete:yolime/<slot>` entries.
- Reparse checks extended to `%LOCALAPPDATA%\Programs` and the shortcut (`yolime.lnk` must not be a link).
- The clean-exit wait goes from 10 s to 15 s (yolime's own exit can take ~9 s: a history prune plus the clipboard
  hand-back).

### Version
`<Version>0.1.0</Version>` in `Yolime.App.csproj` is the one source. `build-setup.ps1` reads the published exe's
`ProductVersion` (the SDK appends `+<commit sha>`; verified on the first build) and passes it as `/DAppVersion=`.
File: `yolime-setup-0.1.0+abc1234.exe`; Apps & Features: `0.1.0+abc1234`. Bump `<Version>` when a build is worth
naming; two builds at the same version still replace each other's files (the script copies everything).

### Build: `tools/build-setup.ps1 [-PublishDir <folder>] [-SandboxTest] [-Iscc <path>]`
Without `-PublishDir`, empties `artifacts\publish` and publishes Release there. Runs `check-publish.ps1`. Empties
`artifacts\setup`. Finds ISCC (`-Iscc`, `%LOCALAPPDATA%\Programs\Inno Setup 6`, `Program Files (x86)\Inno Setup 6`;
otherwise fails with the winget command), prints its version, compiles, and prints the setup's path and SHA-256.
`check-publish.ps1` also scans `Yolime.Core.dll` (where `AcceptInjected` lives).

### CI
After "Publish and check", `tools/build-setup.ps1 -PublishDir artifacts\publish` on every run (catches `.iss`
breakage). Upload `artifacts\setup\*.exe` only on `push` to `main`, `retention-days: 14`, with
`actions/upload-artifact` pinned by SHA, and its SHA-256 in the job summary. Permissions stay `contents: read`.
GitHub Releases are a later, separate step.

## Tests (Sandbox only; written first)

`run-install-test.ps1` builds both setups from the same staged `pkg` (`build-setup.ps1 -PublishDir`), the shipped
one and `-SandboxTest`, staged by exact name. New cases in `install-test.ps1`:
1. `SetupShipped_Elevated_IsRefused`: the shipped setup, `/VERYSILENT`, in the elevated Sandbox: nonzero exit,
   neither folder exists. (Also proves the bypass isn't in the shipped build.)
2. `Setup_Install`: `Yolime` matches `pkg` file-for-file (relative path + SHA-256); shortcut target, working folder
   and description (read through WScript.Shell); Apps key with `DisplayVersion` = the build's version and an
   `UninstallString` whose exe exists; Run value `"<exe>"`; running from `Yolime` with its welcome window.
3. `Setup_UpgradeWhileRunning`: a file in `Yolime` altered and a stale file planted beforehand; afterwards the tree
   matches `pkg` again, the log says the copy exited (not stopped), and a new copy is running.
4. `Script_OverSetup` and `Setup_OverScript`: the tree matches `pkg`, the Apps entry's uninstaller still exists.
5. `Setup_DirOverride_IsRefused`: `/DIR=C:\victim` with a file in it: nonzero exit, the file is still there.
6. `Setup_ReparseAtApp_IsRefused`: a junction at `Yolime` pointing at a folder with a file: nonzero, file intact.
7. `Setup_Uninstall_KeepsData`: run `unins000.exe /VERYSILENT` and `Wait-Until` (the uninstaller re-runs itself
   from `%TEMP%`, so its exit code returns early) the Apps key and both folders are gone and no `_iu*.tmp` runs;
   shortcut gone; data folders kept; a Run value pointing at `C:\dev` kept.
8. `Setup_Uninstall_RemoveData`: `/REMOVEDATA`: both data folders and a planted `yolime/OPENAI_API_KEY` credential
   are gone.
9. `Setup_UninstallFails_KeepsTheEntry`: a file in `Yolime` held open exclusively: the uninstall fails and the Apps
   key and `unins000.exe` remain.
10. Script: `Script_StartWithWindowsOff_RemovesIt`, and `WhileRunning_IsRefused` now expects exit 2.

Each assertion can fail: the tree comparison fails on the altered file if setup skipped the copy; case 1 fails if the
bypass leaked; cases 5, 6 and 9 plant something a broken setup would destroy or orphan.

Not testable in the Sandbox: SmartScreen (mapped files carry no download mark), the GUI pages and prompts (one manual
look in the Sandbox), and an elevated yolime (the Sandbox user is an administrator).

## README
"Install with setup.exe" above the script section:
- get it from `tools/build-setup.ps1` (needs the .NET SDK and Inno) or the latest `main` CI run's artifact (a zip,
  kept 14 days);
- a downloaded or zip-extracted copy shows SmartScreen's "Windows protected your PC" (More info > Run anyway) for
  every new build; a locally built one doesn't;
- with Smart App Control on, Windows blocks setup and yolime outright (no exception); in evaluation mode it may
  later;
- uninstall from Settings > Apps, which asks whether to delete your data; the setup log is
  `%TEMP%\Setup Log <date> #<n>.txt`; `/VERYSILENT` closes a running yolime without asking.

## v2 review rulings (2026-10-29)
These override the text above where they differ.
1. **Silent means no boxes, by code.** `/SUPPRESSMSGBOXES` only works with `/SILENT`/`/VERYSILENT`, and plain
   `MsgBox` is never suppressed. Every prompt and error branches on `WizardSilent` / `UninstallSilent`: silent
   uninstall keeps data unless `/REMOVEDATA`; silent exit 2 proceeds with `-Force`; refusals and failures go to
   `Log()` and the exit code. The harness passes `/SUPPRESSMSGBOXES` too and has a per-call timeout that kills a
   stuck setup and fails that case, so one dialog can't lose the whole run.
2. **The `/DIR=` check is at the top of `PrepareToInstall`** (`{app}` can't be expanded in `InitializeSetup`).
   Case 5 asserts no `C:\victim\unins000.exe` and no Apps key.
3. **`UninstalledAll` is one static text** naming where kept data lives (Inno has no message setter).
4. **`-RemoveData`** refuses when any `Yolime.App` runs in the session (a dev copy holds `history.db` and the same
   keys); runs only after the program removal succeeded; guards each path like `App.Wipe` (fully qualified, leaf
   `Yolime`, parent the known folder, not a reparse point); checks with `Test-Path` after `rmdir`, not its exit code.
   New cases: a junction inside `%LOCALAPPDATA%\Yolime` (its target survives), `%APPDATA%\Yolime` itself a junction
   (refused), a copy running from elsewhere (refused, data intact).
5. **A missing script or failed PowerShell start** at uninstall: "yolime's uninstall files are missing. Remove the
   Apps entry anyway?" (silent: yes). The hard stop is only for "the script ran and refused".
6. **Progress.** A marquee progress page around the script, `ExecAndLogOutput` feeding each script line to the
   status text and Inno's log (this replaces `-LogFile`; case 3 reads the `/LOG` file). Cancel disabled while it
   runs. `install.ps1` gains `-Move` so the extracted `{tmp}\pkg` is renamed into place, not copied again (same
   volume). The 15 s post-launch wait stays (it's how the script knows the app started).
7. **Start with Windows:** `UsePreviousTasks=no`; the box is preset in `CurPageChanged(wpSelectTasks)`: an existing
   `Yolime` folder means upgrade (whoever installed it), and the box mirrors the Run value, unchecked if disabled in
   Task Manager; fresh install checked. "on" also clears a disabled `StartupApproved` value, as
   `StartupRegistry.Enable()` does.
8. **Uninstall order:** program first, data second; nonzero only if the program removal failed. Case 9 also asserts
   `Yolime` is intact. The raise-at-`usUninstall` behaviour is proven by case 9 or replaced.
9. Minor: `[Files]` payload pinned at `DestDir: "{tmp}\pkg"` with `dontcopy recursesubdirs`, first in the section;
   every path quoted in the Params string; `/REMOVEDATA` read by a `ParamStr` loop; the exit-2 prompt's Cancel
   returns "Exit yolime from its tray, then click Back"; the "still running" error adds "if you started yolime as
   administrator, exit it from its tray"; "in History to retry, unless history is paused"; `summary.txt` is plain
   lines in UTF-8 (`[IO.File]::WriteAllLines`), shown in a memo; `DisableReadyPage=yes`; `SetupMutex`;
   `VersionInfoVersion=0.1.0`; case 1 asserts the Sandbox session is elevated first.
