# UI tour v1 (Part 8 of `2026-10-29-release-updates-design.md`)

**Goal.** One Windows Sandbox run that captures every overlay state, every card, every Welcome step and Settings
page, and History, in light and in dark, as cropped PNGs plus an index. The images feed four design-critique agents
and Bryan's findings page. The tour checks that each image shows the state it names; it doesn't test behaviour, which
the existing E2E scenarios cover.

**Sequencing note.** The parent plan put the tour before the Part 6 cut. It hadn't been started by then, and nothing
in it depends on the release, so it lands after, on the public repo, as PR `test/ui-tour`.

**v3.** v2 was revised after three reviews (platform/test validity, UI/UX coverage, hard rules/architecture), v3
after a whole-plan review of v2. Rulings are at the end.

## How states are reached: a named table, staged through the model
Real holds can't keep a state still long enough to capture (Done shows for 1.2 s), and can't produce a long app name
on demand. So the tour stages each state by posting `OverlayInput`s into the overlay's model, which builds the view:
titles, details and buttons come from the real model and `Notices` text. To keep staged states to ones the app can
produce, they come from a **named table** in the app's E2E code, not from a free-form script.

- **`TourStates`** (new, `src/Yolime.App/E2E/TourStates.cs`, whole file under `#if YOLIME_E2E`): name → expected
  `(State, Buttons, OfferUseRaw)` plus a builder `Func<long, IReadOnlyList<OverlayInput>>` taking a base time `T`
  (`OverlayController.NowMs` when applied). Each builder stamps every input from `T` with fixed offsets, the way the
  coordinator would. States that show a clock (Listening, Working, PendingPaste) end with a `Tick` that sets it (e.g.
  `0:04`); Done and the cards get no later `Tick`, since one past 1.2 s (Done) or 4 s (Copied) would hide them.
  Listening entries post their voiced `Level` last, after the `Tick` (`ContextShown`, `CapCountdown` and `ModeChanged`
  rebuild the view without the level, and without a voiced level 2 s of clock shows "No audio" over every other
  line). Entries that show a mode start with `RecordingStarted` in that mode (Preview's title uses it). Run results
  carry a filled `RunTiming` (`OutputWords`, `OutputDoneMs`), an app name and, where the real path has one, a
  `HistoryId`.
- **Hook `tour-state`** (in `E2EMode`): the file holds one table name. The hook, on the UI thread:
  1. resets: posts `UpdatingEnded(null)`, `PreviewEnded`, `PendingPasteEnded`, `Dismissed` (Updating ignores
     `Dismissed`; `UpdatingEnded` without a notice is what leaves it);
  2. posts the state's inputs in order;
  3. in one more queued step, after those, writes `tour-state.done` with the view's `State`, `Buttons` and
     `OfferUseRaw` (enum words only) and whether the notch and pill are visible.
  An unknown name or any exception writes `tour-state.error` with the name and the exception type only, never text.
  The hook has its own catch-all, so a bad entry can't end the app through the timer thread.
- **Freezing time.** A field `TestFreezeTicks`, declared and checked under `#if YOLIME_E2E` (the `TestShrinkPx`
  pattern), makes the controller's own 100 ms timer drop its `Tick`s while the tour runs. `Render` restarting the
  timer then does nothing, and states only move by the `Tick`s the table posts. Set by the hook `tour-freeze`
  (`on`/`off`), also listed below.
- **Cards** go through `tour-state` too, so they get the reset and the state check: an entry `card <show-card spec>`
  takes `Scenarios.CardTable()`'s spec format. It posts a `RunFinished` for run notices and a `NoticeOnly` for the
  notices that only ever arrive outside a run (Busy, Discarded, CapReached, PasswordRefused), as the real paths do.
  The tour's card list is `CardTable()` **minus the tray-only kinds** (`HoldKeyReset`, `SettingsNotSaved`,
  `ElevatedTarget`: AppHost shows them as balloons), **plus** the update cards that are real cards: `UpdateFailed` and
  `UpdateSlow` (via `UpdatingShown` → `UpdatingEnded` with the notice, the real path, so they carry Open the log) and
  `UpdateHoldRefused` (`NoticeOnly` from Hidden). `UpdateAvailable`, `UpdateAvailableElevated`, `Updated` and
  `UpdateAttemptFailed` are balloon-only (`Updater.Tell` → `_tray.Show`), so they go to the critics' brief as text,
  not as staged cards.
- **`probe-theme`**: answers with the notch's and pill's theme as `ApplyTheme` last set it (`light`/`dark`/
  `contrast`) and the fill colour, from two fields that `ApplyTheme` writes under `#if YOLIME_E2E`.
- **`set-capture-hidden`** (`true`/`false`): calls the windows' `SetExcludeFromCapture` and answers with the Win32
  result (`ApplyCaptureSetting` discards it).

**Release checks.** `ReleaseHasNoTestCodeTests`: add `tour-state`, `tour-freeze`, `probe-theme`,
`set-capture-hidden` to `AppHookFiles` (each a whole literal in the code), `TourStates` to `AppTestTypes`, and the new
field names (`TestFreezeTicks` and the two theme fields) to both `ReadMembers` assertions. `check-publish.ps1` gets one
tour marker (`tour-state`), as it keeps a subset on purpose.

## The overlay states (each pass: light, then dark)
Crop: the notch's window rect plus the pill's when visible, physical pixels, 8 px margin. The table's entries:

1. **Listening:** each mode (Dictate, Prompt, Reply, Raw) with a mid level (RMS 0.015, voiced so the silence hint
   doesn't replace the line); latched ("Tap to stop"); mic starting (`MicReady: false`, a `Tick` past 300 ms, no
   `Level`); mic not responding (`MicReady: false`, then `AudioFlowing Delivered=false`); no audio ("is the mic
   muted?", a `Tick` past 2 s and only a silent `Level`); cap countdown.
2. **Reply context:** from selection, from clipboard, skipped (secret), none.
3. **Working:** transcribing (after `RecordingEnded`); transcript shown; writing for the app with a streamed delta (two
   deltas 300 ms apart, so the throttle shows the second).
4. **Done:** pasted (with words and seconds); copied; rewritten-and-pasted with the Use raw pill (`HistoryId` set).
5. **Preview** short and long (over 260 DIP, scrolls); **PendingPaste**.
6. **Long text:** a 60-character app name in Listening's title, in "Writing for {app}…" and in Done's title; the same
   name with a Reply context (title wrap plus the context line); an unbroken 200-character URL in Preview (and a
   streamed line of 120 characters, the most the model shows: the context is cut to 60 and the transcript line to
   120, so longer input there tests nothing more).
7. **Cards** (the list above).
8. **Updating**, the last overlay step of each pass.

Not captured: the Use raw pill on its own after Done times out (the pill-only state has no notch to check against).

Each entry's expected `(State, Buttons, OfferUseRaw)` is checked against `tour-state.done` before capture, and the
notch must be visible; a mismatch fails the entry with both values, and nothing is captured. After `.done`, the
harness waits 400 ms for the island to lay out (as `CheckCard` does) before capturing. After the last overlay entry,
`tour-freeze off` and a reset to Hidden come before the windows, so neither the notch nor a left-over Updating card
is in a window crop or swallows the History runs.

## The windows
- **Welcome:** a fresh app with `--test-first-run`; each of its five steps (Keys, Mic, Hold, Practice, Done), moved
  through by UI Automation with the step's own buttons.
- **Settings:** each of its five pages, opened from the tray command and selected through UI Automation.
- **History:** four real runs first, into the harness's target form: Dictate (a plain hold), Prompt and Reply (Shift
  tapped once and twice during the hold; Reply takes the fresh clipboard as context), Raw (three taps, then Enter on
  its preview). The tour app is started with `--test-rewrite` and a long `--test-transcript` (a sentence ending in a
  200-character URL), so every row's text is long, which is what History's fixed column needs to show. The tour has
  its own small run helper that waits on the run count and the delivery, since the main scenarios' helpers compare
  against the fixed `Spoken`/`Transcript` strings. The staged overlay states don't use the transcript. Then History
  is opened from the tray.
- Crop: `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` (the visible frame, not `GetWindowRect`'s resize
  borders). The harness's target form is minimised before each window capture, and the window is brought to the
  front; `IsWindowVisible` and a UIA lookup by title must both pass.
- The windows use Mica, which may fall back to a solid colour in the Sandbox; the index says so. The Sandbox has no
  audio input, so Welcome's Mic step shows its no-mic state; the index says that too.
- Each app launch first waits for the previous `Yolime.App` to exit (single instance), as `KeepMicReadyRun` does.

## Capture-hiding control
Once, in light: stage the `DidntHear` card; capture it (A). `set-capture-hidden true` answers in
`set-capture-hidden.done` with the Win32 result and, like `tour-state.done`, the view's state and buttons; it must
say success, `Error`, and the notch visible (the harness checks `IsWindowVisible` itself too); capture again (B). Dismiss; capture the same
rect (C). Pass when B differs from A in more than 20% of pixels and matches C within 2%. Then `set-capture-hidden
false`, answered with success, before anything else is captured. (`WDA_EXCLUDEFROMCAPTURE` drops the window from GDI
captures rather than blacking it out; the parent plan's "black" was `WDA_MONITOR`.)

## Theme switching
In the harness, which only runs as the Sandbox user: write
`HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` `AppsUseLightTheme` and `SystemUsesLightTheme`
(1 light, 0 dark), then start a fresh app with its own data folder, as `CardsAtTextScale` does with text size; a
`finally` restores both. Each launch waits out the 20 s startup toast as the main run does.

## Image checks (each fails its image)
- The state check above (overlay) or the visibility and title check (windows), before capture.
- Not uniform: fewer than 98% of pixels within 4 of the most common colour.
- Overlay theme: `probe-theme` names the pass's theme, and the fill pixel at crop (margin + 8, mid-height) is within 6
  of that theme's grey (249 light, 32 dark). The pill isn't fill-checked (its button covers that point).
- Windows: mean luminance above 128 in light, below 128 in dark, plus the visibility check (so an undrawn frame fails).
- The light and dark images of each entry differ in more than 20% of pixels.
- Every entry produced its image; a missing one fails.

## Output and privacy
`artifacts/e2e-tour-results/` (gitignored): `<area>/<entry>-<theme>.png` and `tour-index.json`, holding per image its
area, entry name, theme, rect, the probe's words and numbers, character counts, and the check results; no UI text.
`tour-state.error` carries the entry name and exception type only. The staged strings are fixed fake text in
`TourStates.cs`.

## For the critics (not from images)
The critique brief adds what a still can't show, generated from the code: each card's display time (`min(15 s,
max(minimum, 6 s + 40 ms × chars))`, minimum 6 s for run results and 3 s for notices; Done 1.2 s, Copied 4 s, Use raw
5 s, UpdateSlow until dismissed; hover pauses), the keys (Preview's Enter, Esc, C; Retry is a tap of the hotkey;
Dismiss and Use raw have none; buttons aren't tab stops), the tray menu's items, and the balloon (`onCard: false`)
text of every notice.

## Runner
`run-e2e.ps1 -Tour [-Areas overlay,cards,windows]`: refuses `-Tour` with `-Updates` or `-Only`; own stage
(`artifacts/e2e-tour`) and results folders; the harness started with `--tour`; a 40-minute deadline. A later fix PR
re-runs only its area.

## Not in v1
High contrast and the frame bursts (the parent plan's ruling); windows at 150% text (cards at 150% are covered by
`Cards_FitAt150PercentText`; windows aren't, and that's a gap recorded for a later tour); the scrolled Preview; empty
History.

## Verification
- The tour run is green, and the image count equals (overlay entries + cards + 5 Welcome steps + 5 Settings pages +
  History) × 2 themes, plus the control's 3 images.
- Negative controls, run once and recorded in the PR: an entry whose expected state is wrong fails; a blank crop fails
  the uniform check; skipping the dark registry write fails the theme check.
- Core tests (including `ReleaseHasNoTestCodeTests` against Release and E2E builds) pass; CI is green.

## Review rulings (v2)
- Free-form input script → named table (architecture review): the critics must only see states the app can reach.
- Stopping the timer → `TestFreezeTicks` gate in the tick handler (all three reviews: `Render` restarts the timer).
- Updating can't be dismissed → reset with `UpdatingEnded(null)`, and Updating is last (UI/UX and platform: Critical).
- No state check → each entry asserts its view before capture (platform and UI/UX).
- Added: update cards, all Welcome steps and Settings pages, a critique brief for timing and keys (UI/UX).
- Not taken: the windows at 150% text (recorded as a gap above, to keep v1 to the parent plan's scope).

## Review rulings (v3, whole-plan review)
- Balloon-only notices (four update kinds, and the tray-only `HoldKeyReset`, `SettingsNotSaved`, `ElevatedTarget`)
  aren't staged as cards; the critics get their text.
- Cards go through `tour-state` (reset + state check), so nothing after Updating is silently swallowed; Updating is
  the last overlay entry.
- Builders: voiced `Level` last; no clock `Tick` after Done or a card; `MicReady: false` where the mic line needs it.
- History: `--test-rewrite`, tapped Shift, the tour's own run helper; reset and unfreeze before the windows; a 400 ms
  settle before every overlay capture; the capture control's answer is defined.

## Review rulings (v3 review, folded into the code)
- The state triple can't tell Listening variants (or most cards) apart, so each entry also carries a `Shows` check on
  the view's title, detail, elapsed or preview, run in the app; a failure reports "text differs" with lengths only.
- Mic starting: a clock `Tick` at 800 ms (a real mic not ready by 2 s turns into "not responding"). Mic not
  responding: no `Level` (any buffer clears it). Cap countdown: at 1:52 of a held recording (the cap is 2:00, the
  countdown starts 10 s before).
- `CapWarning` isn't a card with the overlay up (the coordinator posts a countdown instead): left out with the
  tray-only kinds. The `NoticeOnly` kinds are the full list from the call sites (adds RetryUnavailable,
  PasteLastUnavailable, Copied, CopiedAdminWindow, PreviewKept, RawCopied, MicFallback); a non-retryable card renders
  the same either way.
- An exception inside the model's `Apply` runs on its own dispatcher item, outside the hook's catch; it takes the app
  down, and the tour then fails loudly on the missing answer. Accepted: loud, not silent.
